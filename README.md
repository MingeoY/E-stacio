# E-stacio（世语驿站）

**E-stacio** 是一个世界语（Esperanto）学习工具：由系统内置的句子按**词素级**拆解，并由用户把每个词素替换为对应的汉字，让世界语句子呈现出"汉字化"的形态，帮助汉字文化圈母语者以全新的方式理解和记忆世界语构词法。

> **在线体验**：https://mingeoy.github.io/E-stacio/
>
> ✅ 当前状态：核心学习功能与社区贡献机制均已可用。社区数据通过仓库根目录的 `community-data.json` 基线文件实现跨浏览器同步（详见文末"社区数据如何同步"）。
> 🔊 例句朗读使用浏览器原生语音合成，发音质量因浏览器而异。

## 快速上手

1. 打开网页，从左侧抽屉面板（Panelo）选择例句，或直接使用默认句子
2. 点击句子中的词素，为其选用一个汉字替换；编辑器中的"参考选择"会优先展示社区实时贡献
3. 相同词素（同基本形 `b` 且同词尾类型 `n`）会**自动同步**到所有句子和词汇表
4. 底部输入框可切换句子、按序号跳转

**快捷键**：`←` / `→` 切换上/下一句，`空格` 朗读当前句，编辑器内 `Enter` 保存、`Esc` 关闭。

**复制分享**：句子上方的 📋 按钮支持两种格式——「汉字替换」输出纯汉字化文本，「括号标注」输出 `汉字(词素)` 对照文本。

**三种模式**：

| 模式 | 说明 |
|------|------|
| 游客（Sensaluti） | 替换数据仅保存在本地，不上传共享 |
| 登录（Ensaluti） | 输入用户名，私有映射库持久化保存，每次替换同时记为一票社区贡献 |
| 管理（Administri） | 仅限白名单管理员账号，可编辑词素数据、导入导出句包、重置数据 |

## 核心特性

- **词素级汉字替换**：按基本形 `b` + 词尾类型 `n` 匹配，`n=0` 为特殊词尾（涉及复数、宾格的合并或拆分问题），`n>0` 为普通词素；`d` 字段仅用于例句展示，所有底层键一律以 `b` 为准
- **全局同步替换**：某句某词素选用汉字后，所有句子与词汇表中的同词素实时同步
- **三层映射库**：社区公开库（投票制——同词素多人选择时取最高票，同票取最近贡献）+ 用户私有库（覆盖公开库）+ 仓库基线（跨浏览器同步），合并后生效
- **词汇表随模式自适应**：合并模式展示 `n=0` 整体词尾，拆分模式展示 `n=-1` 拆分字符，`n>0` 普通词素始终单独一组；支持按字母或汉字笔画排序，点击词条弹出相关例句并可直接跳转
- **社区贡献页**：一览全部贡献数据（键数 / 票数 / 参与用户数统计、各候选票数与贡献者、当前生效标记），并提供「导入贡献包」「导出基线」维护入口
- **多语言界面**：中 / 英 / 日三语辅助翻译 + 世界语界面标签，世界语 TTS 朗读
- **抽屉式面板**：例句列表 + 词汇表默认收起，主页面占满窗口宽度
- **管理面板**：编辑词素（拖动排序、插入、删除）、按 id 合并导入句包、导出本句/所选句、一键重置
- **关于面板**：项目简介与当前例句库规模，随数据动态更新

## 技术实现

纯前端静态页面，无构建、无框架依赖：单 HTML 主程序 + 外置数据 JS，通过 `localStorage` 实现数据持久化与同浏览器跨用户共享，另以仓库内的 `community-data.json` 基线文件实现跨浏览器社区同步。核心匹配逻辑：每个词素以 `b|n` 为键存入映射库，渲染时统一查表替换；数据文件通过 `?v=版本号` 参数引用，更新数据文件时递增版本号即可避免旧缓存干扰。

### 项目结构

```
E-stacio/
├── index.html            # 主程序（界面 + 全部逻辑）
├── e-stacio-data.js      # 多语言包 + 368 句例句（含 3 句补充专名/词汇句）+ 特殊词尾默认候选
├── community-data.json   # 社区贡献基线（v2 投票制结构，随仓库分发）
└── README.md             # 本文件
```

### 数据存储（localStorage 键）

| 键 | 内容 |
|------|------|
| `e-stacio-state` | 游客模式的状态与私有替换（含界面语言、合并/拆分模式、当前句序号等） |
| `user-{用户名}` | 登录用户的私有映射库与逐位置覆盖 |
| `e-stacio-public` | 本机社区贡献库，v2 结构 `{ v:2, contrib: { "b\|n": { 字符: { c:票数, u:{用户:时间戳} } } } }`，兼容 v1 平铺结构自动迁移 |
| `e-stacio-sentences` | 当前例句库（导入句包后持久化，重置时回退内置数据） |

有效映射 = 社区公开有效值 ∪ 本机私有替换（私有优先）；逐位置覆盖（`replacements`）用于单句重置场景，优先级最高。

### 复数与宾格词尾的合并（`n=0`）与拆分（`n=-1`）

世界语用 `-j` 标记复数、`-n` 标记宾格，二者常与词性词尾叠加出现（如 `ojn` = `o` + `j` + `n`）。对这类**特殊词尾**，程序提供两种处理模式，可通过设置栏 **Divida / Kuniga** 按钮切换：

- **合并模式（Kuniga）**：特殊词尾按整体显示与替换，如 `ojn`、`ajn`、`on` 各作为一个完整单元
- **拆分模式（Divida）**：将 `n=0` 且长度大于 1 的特殊词尾按字符拆分为独立单元，分别替换。例如：
  - `ojn` → `o`、`j`、`n`
  - `on` → `o`、`n`
  - `en` → `e`、`n`
  - 人称代词宾格（如 `min`）中的 `-n` 同样拆分，代词词干 `mi` 保持独立

共 15 个特殊词尾固定编号 `n=0`：`n` `e` `en` `o` `oj` `on` `ojn` `a` `aj` `an` `ajn` `u` `uj` `un` `ujn`。系统按 `n===0 且长度>1` 自动判定拆分，无需硬编码名单；拆分模式下，替换键按**拆分字符**同步（如所有词尾中的 `n` 统一映射）。拆分模式的字符使用独立键（`n=-1`）：`a` `e` `o` `u` `j` `n`，两种模式的键空间完全隔离，切换模式互不影响各自的汉字化设置。

### 同形（`b`相同）异义（`n`不同）词素

同一个基本形在不同语境中可能是完全不同的语素。程序用频率编号 `n` 区分它们，各自独立替换、互不影响（编号规则：特殊词尾从 0 起，普通词素参考出现频率从 1 起递增）。当前数据中出现的全部组：

| 基本形`b` | 编号`n` | 含义 | 示例 |
|--------|-----|------|------|
| `ajn` | 0 | 特殊词尾（形容词复数宾格） | `grand-ajn`、`mult-ajn` |
| `ajn` | 1 | 虚词"任何" | `iu ajn`（暂未出现在当前例句中） |
| `al` | 1 | 相关词词尾 | `i-al`（ial 因此） |
| `al` | 2 | 介词"向……" | `al la kongreso`、`al-ven-i`（到达） |
| `am` | 1 | 相关词词尾（时间） | `ĉi-am`（ĉiam 总是） |
| `am` | 2 | 动词词根"爱" | `mi amas vin`、`Am-o`（爱情） |
| `an` | 0 | 特殊词尾（形容词单数宾格） | `bon-an`、`grand-an` |
| `an` | 1 | 词缀（居民/成员） | `polic-an-o`（警察）、`vegetar-an-o`（素食者） |
| `ĉi` | 1 | 相关词前缀 | `ĉi-u`、`ĉi-o`、`ĉi-am` |
| `ĉi` | 2 | 虚词"这" | `ĉi tie`（这里）、`ĉi tiu`（这个） |
| `el` | 1 | 相关词词尾 | `ki-el`（kiel 如何） |
| `el` | 2 | 介词"从……" | `el la arboj`、`el-ir-ejo`（出口） |
| `en` | 0 | 方向副词词尾 | `antaŭ-en`（向前） |
| `en` | 1 | 介词"在……里" | `en Afriko` |
| `i` | 1 | 动词不定式词尾 | `labor-i`、`lern-i` |
| `i` | 2 | 相关词词根 | `i-om`（iom 些许）、`i-al`（ial 因此） |
| `i` | 3 | 国家名后缀 | `Franc-i-o`、`Ĉin-i-o` |
| `on` | 0 | 特殊词尾（名词单数宾格） | `salut-on`、`Esperant-on` |
| `on` | 1 | 词缀（分数） | `kvar-on-o`（四分之一） |
| `u` | 0 | 相关词词尾 | `ĉi-u`、`ti-u` |
| `u` | 1 | 动词命令式词尾 | `pardon-u`、`vizit-u` |
| `uj` | 0 | 特殊词尾（相关词复数） | `ĉi-uj`、`ti-ujn` |
| `uj` | 1 | 词缀（容器） | `dosier-uj-o`（文件夹）、`kaf-uj-o`（咖啡壶） |

同一基本形的不同编号在替换时互不干扰：例如`kiel` 中的相关词尾（`el`, n=1）与 `el la arboj` 中的介词（`el`, n=2）仍各自独立设置。

## 路线图

### 短期
- **扩充例句库**：从当前 368 句扩充至 500+ 句，覆盖更多日常场景与语法结构
- **✅ 社区贡献库（已完成）**：公开映射库采用贡献制结构 `{ "b|n": { 字符: { c:票数, u:{用户:时间戳} } } }`，登录用户每次替换计一票，有效公开值取最高票（同票取最近贡献）；编辑器"参考选择"中实时贡献优先展示，合并模式另有 15 个 `n=0` 特殊词尾的默认候选字符（`COMMUNITY_DATA`，仅建议不应用）；社区数据通过 `community-data.json` 基线文件跨浏览器同步，并支持导入贡献包合并
- **更多辅助语言**：在现有中/英/日基础上增加其他辅助翻译语言

### 中期
- **多课程包切换**：按难度分级（入门 / 进阶 / 专题）组织课程包，支持用户自选加载
- **社区数据汇总与审核**：统计公开库中各词素的候选汉字使用频率，生成"热门映射"排行榜，引入投票或管理员审核机制保证质量
- **智能候选汉字**：根据词素语义、用户历史选择与社区偏好，智能排序候选汉字列表，减少翻找成本

### 长期
- **后端 API**：将数据存储与共享从 localStorage 迁移至真实后端（账号体系、云端同步、跨设备漫游）
- **PWA**：支持离线使用与桌面/主屏安装
- **移动端优化**：针对手机屏幕的触控交互与布局适配
- **高质量 TTS**：接入 ElevenLabs 等神经网络语音，替换浏览器原生 TTS，提供更自然的世界语朗读

## 社区数据如何同步

社区贡献数据分两层：**本机层**（浏览器 localStorage 中的投票制贡献库，`e-stacio-public`）与**仓库基线层**（根目录的 `community-data.json`）。页面每次启动会拉取基线文件并与本机贡献库按用户名合并——这就是跨浏览器看到他人贡献的通道。

**贡献者**：登录后在"社区贡献"页点击**导出基线**，把得到的 `community-data.json` 发给维护者（文件内含本机全部贡献记录，按用户名区分，合并不冲突）。

**维护者**（无需任何本地工具链，全程浏览器内完成）：
1. 打开网页"社区贡献"页 → **导入贡献包**，选择贡献者的导出文件（仅合并其贡献数据，不影响本地例句与私有替换）
2. 确认贡献列表无误后 → **导出基线**，得到新的 `community-data.json`
3. 用它覆盖仓库根目录同名文件，提交 push——Pages 自动更新，所有访客下次打开即可看到

基线与本机数据的优先级：本机私有替换 > 本机贡献投票 > 仓库基线。拉取失败（断网、`file://` 打开）时静默沿用本机数据，不影响学习。
